# 任务清单

每个任务包含：仓库、模式、依赖、规格依据、交付物、验收标准。Claude Code 以验收标准作为完成依据（见 workspace/CLAUDE.md 的“完成的定义”）。

## 使用方式
- 单个任务：`执行 backlog/M1.md 中的 M1-03。先给出计划，确认后实施。`
- 里程碑顺序（控制面优先，ADR 0013）：M0 → M1 控制面与两端前端 → M2 节点编排（模拟 Agent）→ M3 Agent 改造与 v0.1 → M4 → M5。
- 组队任务：`按 M1-06 组建 agent team：spec-owner、panel-backend、frontend、e2e-tester。任务列表按验收标准拆分。`
- 并行工作流：`按 workflows/spec-review.md 创建并运行 workflow。`

## 里程碑

| 里程碑 | 时长 | 内容 | 产出 |
|---|---|---|---|
| M0 | 2 周 | 规格评审、建仓与 CI、契约（proto、客户端与管理接口）、控制面与前端骨架、Mock、模拟 Agent、Xboard-Node 审计 | 可以开始写业务代码 |
| M1 | 6 周 | 控制面核心与两个前端：账号、设备、套餐、权益、报价、订单、支付宝当面付、余额、优惠券、兑换码、通知、权限与审计 | 不含节点的完整商业闭环 |
| M2 | 4 周 | 节点编排与计量（模拟 Agent）：接入、网关、内核选择、同步、权限协调、入账、导出；后台节点页面 | 节点协议 v1 候选 |
| M3 | 5 周 | 改造 Xboard-Node fork：通信层、接入、选内核、WAL、租约、安装 | v0.1 |
| M4 | 4 周 | 运营完善：公告、工单、帮助、到期提醒与自动续费、流量包、支付对账、看板 | v0.2 |
| M5 | 5 周 | 可扩展：多实例网关、长轮询、机器模式、自升级、返利、备份、Helm、基准 | v0.3 |
| v1.0 | — | 冻结协议与接口；迁移工具 | 稳定承诺 |

时长按 2–3 名核心开发者估算。

## 主要风险

| 风险 | 缓解 |
|---|---|
| Xboard-Node 内核集成不满足 AGT-12 | M0-04 逐项验证，缺口在内核 fork 中补 |
| 与上游分叉后难以吸收修复 | AGT-01 新代码放新包、改动登记；每月挑选合入（`upstream-sync`） |
| 模拟 Agent 与真实 Agent 行为不一致 | 两者运行同一协议一致性套件 |
| 首个可部署版本较晚（M3 结束） | M1 结束即可演示；M2 可用模拟 Agent 完整试运行 |
| 计费错误或折算纠纷 | 性质测试、对抗工作流、报价展示完整明细 |
| 控制面被入侵 | 管理员强制二次验证、敏感字段加密、依赖扫描、发版审计 |

## 状态
在任务标题后标注：`[待办]`、`[进行中 @分支名]`、`[已完成 PR#]`。完成后在 PR 中逐条说明验收标准的验证方式与涉及的规则编号。
