## M3-10 多入站与凭据模型重构（以凭据 ID 为键）[待办]
- 仓库：node-agent
- 模式：单会话 + concurrency-reviewer
- 依赖：M0-04（FORK_PLAN 第 7 节）；panel-spec v0.2.0（凭据施加于全部入站、`Credential` 各协议形式、mKCP `finalmask`）。M3-03、M3-06 依赖本任务；可与 M3-01 并行，接入 M3-01 的通信层前以快照文件或测试桩驱动。
- 规格：spec/21（21.3、AGT-07、AGT-13、AGT-15）、spec/20 NODE-15、NODE-24
- 内容：
  - `model.NodeSpec`（一个节点一个入站）改为 `InboundSet`：多个入站，按 `tag` 与 `version` 标识；
  - `Inbound.settings_json` 按 `panel-spec/schemas/inbound/` 转换为两个内核的配置，包括 mKCP 的 `finalmask`；
  - 内核接口的身份键从上游的整数用户 ID 改为凭据 ID（`Credential.id`），计量、限速、来源追踪都以凭据 ID 为键；
  - 按 AGT-15 把每条凭据施加于全部入站，`Credential.secret` 与 `ss2022_key_16`、`ss2022_key_32` 按 proto 注释编码，两个内核一致，Agent 不做派生；
  - `ApplyInbounds` 逐入站替换，只中断被修改或删除的入站上的连接。
- 验收：
  1. 一个节点同时运行多个入站（至少 VLESS/TCP + Reality、Shadowsocks 2022、Hysteria2），两个内核各自在其支持的组合上加载成功。
  2. 修改或删除一个入站只中断该入站上的连接，其他入站的已有连接不受影响（测试断言）。
  3. 同一凭据可在节点的每个入站上认证；移除凭据后，所有入站上该凭据的连接都在 1 秒内关闭（NODE-24；关闭能力本身由 M3-06 补齐，本任务提供按凭据 ID 聚合的连接登记）。
  4. 对 `testdata/node-v1-vectors.json` 的 `credential` 向量，两个内核生成的用户配置（UUID 文本、各协议密码、SS2022 用户密钥）逐项相等。
  5. 按旧版 `header_type`、`seed` 生成 mKCP 配置的代码删除；`finalmask` 按 `[header, obfs]` 写入 Xray 配置；`panel-spec` `testdata/mkcp-finalmask.json` 中每个用例的 `xray_udp` 作为 `streamSettings.finalmask.udp` 都能通过 Xray `conf.StreamConfig.Build` 加载，且 Agent 生成的结果与之相等（测试）。
  6. `go test -race` 通过，concurrency-reviewer 无阻断意见。

## M3-11 依赖与内核升级，修复 govulncheck 报告的漏洞 [待办]
- 仓库：node-agent、sing-box、xray-core（每个仓库分别提交，ARC-02）
- 模式：单会话，按 `core-upgrade` Skill 处理
- 依赖：M0-02（node-agent CI 中 `govulncheck` 以非阻塞方式运行）。与 M3-06 协调：若在 M3-06 之后进行，`PATCHES.md` 中的补丁按 `core-upgrade` 第 1–2 步 rebase 到新基点。
- 规格：spec/21 AGT-03、AGT-04，spec/42 42.2，spec/02 CONV-25
- 内容：
  - M0-02 时 node-agent 的 `govulncheck` 报告 14 个依赖漏洞（`golang.org/x/crypto`、`golang.org/x/net` 等），修复需要升级 node-agent 的直接依赖并升级两个内核 fork；
  - 内核按 `core-upgrade` 跟随上游或自行 rebase，打 `<上游版本>-panel.<序号>` tag，node-agent 的 `replace` 指向新 tag；
  - 每个内核 fork 在同一提交中更新 panel-ci workflow 的 `UPSTREAM_BASE`（CONV-25、AGT-04）。
- 验收：
  1. node-agent 的 `govulncheck ./...` 没有报告可达的漏洞；无法修复的项（上游尚无修复版本）逐项在 PR 中记录原因与跟踪链接。
  2. node-agent CI 中 `govulncheck` 改为阻塞。
  3. `make test && make conformance` 通过；上游行为变化记录到 `node-agent/internal/kernel/CLAUDE.md` 的“已知差异”。
  4. 两个内核 fork 的 `UPSTREAM_BASE` 与新的上游基点一致，SPDX 检查通过。
