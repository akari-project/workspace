# 32 前端

适用范围：`panel/web`（pnpm workspace：`portal`、`admin`、`ui`、`sdk`）。

## 32.1 通用要求

- **UI-01** 只通过 `@panel/sdk`（由 OpenAPI 生成）调用接口，不手写请求。后端未完成时，用 `pnpm mock`（Prism 按 OpenAPI 与示例启动）开发。
- **UI-02** 每个数据视图有加载、空、错误三种状态；错误按 `code` 显示本地化文案，并显示 `request_id`。
- **UI-03** 危险操作二次确认，并展示影响范围（例如“将影响 312 名用户”，来自 spec/31 CON-07）。这是防误操作的界面措施；服务端的控制见 spec/10 AUTH-19。
- **UI-04** 文案全部走 i18next，至少提供 zh-CN 与 en；日期、金额、流量按用户语言与时区格式化。金额与流量只做显示格式化，前端不计算折算。
- **UI-05** 深浅色主题；键盘可操作；表单错误与字段关联；对比度满足 WCAG AA。用户中心移动端优先，管理后台桌面端优先。
- **UI-06** 构建产物嵌入控制面二进制（spec/40）：资源使用相对路径；运行时配置从服务端注入的 `window.__PANEL_CONFIG__` 读取，不在构建时写死域名。前端在分块加载失败时刷新 `index.html`（spec/40 DEP-03）。
- **UI-07** 页脚显示“源代码”链接（spec/01 ARC-04）。
- **UI-08** 刷新令牌的并发控制：同一浏览器中多个标签页通过 Web Locks 或 BroadcastChannel 保证同一时间只有一个刷新请求（spec/10 AUTH-07）。
- **UI-09** 需要重新验证的操作（spec/10 AUTH-23）收到 `mfa_required` 时，弹出验证框，完成后自动重试原操作。管理后台的敏感操作（spec/10 AUTH-19）同样处理：弹出 TOTP 输入框，调用 `POST /v1/staff/me/step-up` 取得 `Mfa-Assertion` 后带上重试；有效期内的 `Mfa-Assertion` 复用于后续敏感操作，只保存在内存中。

## 32.2 用户中心（portal）

| 页面 | 里程碑 | 内容 |
|---|---|---|
| 注册、登录、邮箱验证、找回密码 | M1 | 二次验证挑战（TOTP、恢复码；Passkey 在 M4）；邀请码（注册策略要求时）；重新发送验证码 |
| 设备授权 `/activate` | M1 | 输入 `user_code` 批准电视等设备（spec/10 AUTH-24） |
| 扫码批准 | M1 | 显示请求设备的平台、型号、IP 前缀与地区，选择与新设备一致的校验数字 |
| 概览 | M1 / M2 | 当前套餐、到期、剩余流量、到期提醒；M2 起显示近 7 天用量 |
| 套餐 | M1 | 对比、周期选择、可访问地区数；已购用户显示续费、升级、降级与锁定价格 |
| 确认购买 | M1 | 报价明细（原价、剩余价值抵扣、优惠、余额抵扣、应付、开通后到期时间；改换周期时提示“原锁定价格将失效”）；报价倒计时 |
| 支付 | M1 | 支付宝二维码与倒计时；移动端“打开支付宝”；轮询订单状态；过期后可以重新下单 |
| 我的权益 | M1 / M4 | 当前权益、下一段（可取消）、自动续费开关；M4 起显示流量包与额外设备 |
| 订单、余额与兑换 | M1 | 订单列表与详情；余额流水（分页）；兑换码 |
| 设备与登录会话 | M1 | 设备列表（含浏览器登录）、最后活跃、移除；设备上限已满时提示 |
| 账号安全、通知偏好 | M1 / M4 | 修改密码、TOTP 与恢复码、注销（M1）；Passkey（M4）；非安全类通知的开关 |
| 连接与导入 | M2 | 第三方导入链接与二维码（默认遮挡）、重置（需要重新验证）、客户端下载说明 |
| 用量 | M2 | 30 天图表、周期进度、按地区分布 |
| 公告、帮助、工单 | M4 | spec/13 |
| 邀请返利 | M5 | spec/13 |
