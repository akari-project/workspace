# 13 运营模块

适用范围：`internal/notify`、`internal/content`、`internal/support`、`internal/referral`。可关闭的模块默认关闭，由运营者在后台开启。

- **OPS-08** 模块关闭时，其客户端接口返回 404 `not_found`。`/v1/config` 的 `features` 中列出各模块是否开启，前端据此隐藏入口。键名为 `announcements`、`articles`、`support`、`referrals`、`diagnostics`。

## 13.1 通知（不可关闭）

- **OPS-01** 统一使用 `Notifier` 接口；内置 SMTP，Telegram 与 Webhook 为内置的可选渠道。
- **OPS-02** 外发消息由业务代码在同一事务中写入 `notification_outbox`，不经过事件主题（CONV-22），由 worker 投递。
  - 失败后指数退避重试，最长 24 小时；验证码与找回密码类消息的最长重试时间等于验证码或链接的有效期。
  - 含令牌、验证码或链接的变量按 CONV-31 加密，投递结束后清除。
- **OPS-03** 模板按语言存放在 `notification_templates`，只允许白名单变量，不执行任意逻辑；后台可编辑与预览（M4）。
- **OPS-04** 通知事件分四类，只有提醒类与营销类可以由用户关闭：

| 类别 | 事件 |
|---|---|
| 安全类 | 注册验证码、找回密码、有人尝试用已注册邮箱注册、新增设备、异常登录、密码或二次验证变更、恢复码不足、导出链接重置、账号暂停与注销 |
| 交易类 | 支付成功、权益开通、到期提醒（7、3、1 天）、自动续费结果、退款、报价失效或迟到付款转入余额、工单回复 |
| 提醒类 | 流量达到 80% 与 100% |
| 营销类 | 公告推送 |

- **OPS-05** 用户的通知偏好保存在 `notification_preferences(account_id, category, channel, is_enabled)` 中，通过 `GET`、`PUT /v1/me/notification-preferences` 读写。安全类与交易类不可关闭。
- **OPS-09** 异常登录：本次登录来源的国家代码与 ASN，与该账号最近 30 天内所有成功登录都不相同。未配置 GeoIP 数据库时，只按“新增设备”通知。

## 13.2 公告（可关闭）

- 支持 Markdown、多语言、置顶、生效与失效时间、目标人群（全部 / 有效用户 / 指定套餐）。
- 客户端从 `/v1/config` 取得最新公告版本号，版本变化时拉取 `/v1/announcements`。该列表只返回生效中的公告，可以不分页（CONV-11）。

## 13.3 工单（可关闭）

- 工单包含主题、分类、内容；客服可以指派处理人。
- **OPS-10** 附件：
  - 只允许 PNG、JPEG、WebP，按文件内容识别类型，不信任扩展名与请求头；单个不超过 5 MB，每条消息最多 4 个；超限返回 413 `payload_too_large`。
  - 先调用 `POST /v1/support/attachments` 上传，取得附件 ID，再在消息中引用。存储在本地或 S3 兼容存储中。
  - 下载需要鉴权，只有工单所有人与拥有 `tickets.*` 权限的管理员可以下载；响应带 `Content-Disposition: attachment` 与 `X-Content-Type-Options: nosniff`。
- **OPS-11** 状态流转：

| 事件 | 结果 |
|---|---|
| 用户创建或回复 | `open` |
| 客服开始处理 | `in_progress` |
| 客服回复 | `waiting_user` |
| 任一方关闭 | `closed` |
| `waiting_user` 超过 7 天 | 自动 `closed` |
| 关闭后 30 天内用户回复 | 重新 `open`；超过 30 天则需新建工单 |

- 客服可以只读查看该用户的套餐、订单、设备与最近 7 天用量，不能查看密码与凭据（对应权限 `accounts.read`，spec/10 AUTH-17）。

## 13.4 帮助文档（可关闭）

- 按分类组织的多语言 Markdown，可以按平台（iOS、Android、Windows、macOS、Linux）筛选。
- **OPS-12** 文章中可以引用白名单变量，例如当前用户的导入链接，由服务端渲染：
  - 未登录时，用户变量渲染为“登录后显示”的占位提示；
  - 响应中含用户变量时带 `Cache-Control: private, no-store`，不参与共享缓存与 ETag；
  - 导入链接默认遮挡显示（spec/32）。

## 13.5 邀请返利（可关闭，默认关，M5）

- 每个账号有一个邀请码；被邀请人注册时绑定，之后不可更改（邀请码也用于“仅邀请码”注册，spec/10 AUTH-02）。
- 规则：比例、仅首单或每单、单人上限。
- **OPS-06** 返利的计算与结算：
  - 基数为该订单通过支付渠道实际支付的金额，不含余额抵扣与优惠，结果向下取整。用返利余额支付的订单不产生返利。
  - 返利先冻结（默认 14 天），期满转入邀请人余额。
  - 冻结期内订单退款：按退款比例作废冻结的返利。已转入余额后才退款：写入等额负向流水（原因 `referral`），余额可以为负；余额为负时不能用于抵扣（spec/12 ORD-15）。
- **OPS-07** 自邀请与可疑判定：
  - 被邀请人与邀请人为同一设备（设备公钥相同）或同一支付账号（`orders.payer_ref_hash` 相同）时，不计返利。
  - 以下情况判为可疑，进入人工审核（`referral_earnings.status='review'`）：注册 IP 的 /24（IPv6 为 /48）前缀相同；同一邀请码 24 小时内注册的账号数超过设定值（默认 5）。
- 提现为可选的人工审核流程，系统只记录，不自动打款。

## 13.6 从其他面板迁移（v1.0 之后）

- 一次性导入工具，放在 `panel/tools/import/`：从 V2Board / Xboard 导入用户、套餐、剩余时长与流量。
- 旧密码哈希在首次登录验证成功后，重新以 argon2id 哈希。
