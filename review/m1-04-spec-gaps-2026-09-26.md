# M1-04 规格缺口评审（2026-09-26）

背景：M1-04（套餐、价格、线路组）开工前，负责人列出规格与契约的缺口 G1–G9，`spec-owner` 对照 spec/11、spec/31、spec/02、spec/03、`00001_init.sql` 与两份 OpenAPI 逐条核对并补充 A–C，负责人裁定。规格修改见本仓库同一提交，契约修改见 panel-spec v0.8.0。

## 裁定

| 编号 | 问题 | 裁定 | 落点 |
|---|---|---|---|
| G1 | CON-09 审计表缺少套餐、价格、线路组的取值 | 新增 `plan.create/update/delete`、`plan_price.create/discontinue`（`target_type` 为 `plan_price`）、`plan_location_group.create/delete`、`plan_rollout.create`、`location_group.create/update/delete`；新建价格行时自动停售旧行只写一条审计，带 `discontinued_price_id` | spec/31 CON-09 |
| G2 | CONV-34 缺少载荷 | `plan.access_changed` = `{schema_version, plan_id}`（`tier` 变更、线路组关联与移除）；`location_group.changed` = `{schema_version, location_group_id}`（`min_tier` 变更）；消费方重算；状态变更不写事件（ACS-01 不看套餐状态） | spec/02 CONV-34 |
| G3 | `deletePlan` 条件与数据库不符：价格行不可删除且外键 RESTRICT；免费套餐没有价格行但有权益 | 只有既没有价格行、也没有权益的套餐可以删除，否则 409 `invalid_state` | spec/11 BIL-26；契约 `deletePlan` |
| G4 | `PlanUpdate` 可改 `kind` | 保留字段；只在没有价格行与权益时可改，否则 409 `invalid_state`；`kind` 与 `tier` 不匹配 400（`tier`、`out_of_range`）；价格行周期须与类型匹配，400（`period`/`period_days`、`not_allowed`）；币种不是站点货币 400（`currency`、`not_allowed`） | BIL-01、BIL-26；契约 |
| G5 | 免费套餐数量未限定 | 至多一个，部分唯一索引 `plans_single_free`；再建返回 400（`kind`、`taken`） | BIL-15、spec/03 3.3 |
| G6 | 上架与停售的约束 | 非免费套餐进入 `on_sale` 须有在售价格（新建时不能直接 `on_sale`）；`on_sale` 套餐停售最后一行在售价格 409；已有权益的套餐不能改回 `draft`；客户端列表跳过没有在售价格的套餐；套餐可以不关联线路组 | BIL-01、BIL-26；契约 |
| G7 | “应用到现有用户”需要新表并写 `admin_adjust`，写入方在 M1-05 | 移入 M1-05；M1-04 只在影响预览中支持 `rollout_fields` | backlog M1-04、M1-05 |
| G8 | 线路组成员需要节点（M2） | 移入 M2-01（后端任务；M2-08 只有前端） | backlog M2-01 |
| G9 | 影响预览的口径 | 按不同账号计，状态 `active`、`over_quota`、`suspended`，与 `active_entitlement_count` 相同；M1 中节点数为 0，凭据增减省略；客户端 `Plan.location_count` 为可访问的不同地区数 | BIL-26、CON-07；契约 |
| ETag | 内嵌子集合与派生计数 | 采用版本列 `plans.version`、`location_groups.version`，由应用在同一事务中加 1，子资源变化使父资源加 1；价格行用 `updated_at`；ETag 只覆盖可编辑状态，派生计数（`active_entitlement_count`、`plan_ids`）不参与；`host_count` 只随增减成员变化，随版本变化 | spec/31 CON-05、spec/03 3.6 |
| A | 免费套餐如何启用未定义（初议为“状态 `on_sale` 即启用”，后发现契约已有 `Settings.free_plan_id`，改判） | 由设置 `free_plan_id` 启用：必须引用唯一的免费套餐（否则 400 `free_plan_id`、`not_allowed`），修改设置时触发批量授予或结束（接线 M1-09，权益逻辑 M1-05）；免费套餐的状态没有启用含义，无论状态如何都不列出、不可报价；被引用的套餐不可删除、不可修改 `kind`（409 `invalid_state`） | BIL-15、BIL-26、spec/03 3.6；backlog M1-04、M1-05、M1-09；契约 |
| B | `node_group_members` 外键 RESTRICT，有成员的线路组删除会失败 | 有成员时同样 409 `invalid_state` | ACS-06；契约 `deleteLocationGroup` |
| C | 客户端 `listPlans` 未说明排除免费套餐 | 补充描述 | 契约 |

| D | 站点初始化没有规定：没有任何流程写入 `site_currency`、`site_timezone` | 结算货币没有隐含默认值；初始化之前需要结算货币的操作（新建价格行，之后的报价与下单）返回 409 `invalid_state`；时区缺键仍按 `Asia/Shanghai` 读取。站点初始化列入 M1-09 交付（后台与命令行，只写一次） | spec/02 CONV-08、BIL-01；backlog M1-09；契约 `createPlanPrice` |
| E | 有 `plans.*` 但没有 `settings.read` 的管理员录入价格时不知道结算货币 | `StaffMe` 增加必填、可空的只读字段 `site_currency`（`null` 表示未初始化，与 `Settings.currency` 互相引用），响应中新增必填字段为非破坏性 | spec/31 认证行；契约 `StaffMe` |
| F | 设置 `currency` 在站点初始化前没有值（`Settings.currency` 为必填、非空） | 不在 v0.8.0 处理：改为可空会被 oasdiff 判为破坏性（`response-property-became-nullable`），CI 以 `--fail-on ERR` 失败。作为 M1-09 站点初始化的 spec-change 问题，与初始化接口一并设计 | backlog M1-09 |
| G | 关闭免费套餐时 `admin_adjust` 没有原因来源；单个事务批量授予或结束不可扩展（protocol-reviewer） | 不在 v0.8.0 处理，契约只写“执行方式由 M1-05/M1-09 定义”。列为 M1-09 前置 spec-change 问题：系统原因文本、敏感操作带原因，或单独的动作子资源加影响预览；worker 分批执行 | backlog M1-09；契约 `Settings.free_plan_id`、`updateSettings` |

其他：管理接口 `GET /v1/plans` 按 `sort`、`id` 升序分页，索引 `plans_sort`；`GET /v1/location-groups` 按 `created_at`、`id` 升序分页；两处都在描述中写明；加购项价格仍属 M4-04（spec/11 11.8）。

## 迁移（M1-04 实现，已与 panel 71cea78 对齐）

- 普通迁移（panel 00006）：`plans.version`、`location_groups.version`（`bigint NOT NULL DEFAULT 1`，CHECK `version > 0`）；新触发器 `plan_prices_period_guard` 检查周期与类型匹配（`plan_prices_plan_guard` 保留）；`plans_kind_guard` 改为已有价格行时不能修改 `kind`，其余条件由应用检查。
- `NO TRANSACTION` 迁移（panel 00007）：`CREATE UNIQUE INDEX CONCURRENTLY plans_single_free ON plans (kind) WHERE kind = 'free'`、`CREATE INDEX CONCURRENTLY plans_sort ON plans (sort, id)`（CONV-21）。
