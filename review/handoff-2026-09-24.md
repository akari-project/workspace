要点：

- **浏览器刷新令牌**：浏览器得到 `CookieTokenRefresh`，响应体不含令牌。
- **SMTP**：`tls` 缺省为 `starttls`，要求加密。
- **设备签名**：设备签名带域分隔前缀。
- **重新验证（AUTH-23）**：
  - 覆盖开始绑定二次验证。
  - 以密码完成的登录算一次重新验证；设备授权与扫码登录不算。
  - 刷新只沿用剩余时间，不延长。
- **`/v1/config`（API-11）**：
  - 备用接口地址放部署配置 `client.api_endpoints`，不进后台。
  - `announcement_version` 在公告模块实现前为 0。
  - `issued_at` 取 settings 键 `config_issued_at`。
  - 签名密钥为 `PANEL_CONFIG_KEY`：缺少时 api 角色拒绝启动，与访问令牌密钥必须不同。
- **426（API-03）**：只用于契约列出的四个入口操作。由哪些操作检查，由 tools/oapiprep 从契约生成（`VersionChecked`）。

## 环境与操作注意

- **发布与推送的限制**：
  - 会话令牌不能推送 tag。panel-spec 的版本 tag 由负责人在 GitHub 创建 release。
  - 会话令牌也不能推送 `.github/workflows/*` 的改动。
- **契约变更流程（spec-change）**：
  1. workspace 规格；
  2. panel-spec OpenAPI 与 CHANGELOG（四部分：新增、变更、修复、安全，外加迁移与在线执行说明）；
  3. protocol-reviewer 审查；
  4. 两个 PR；
  5. 负责人打 tag；
  6. panel 升级：`go get github.com/akari-project/panel-spec@vX`，在 `web` 目录执行 `pnpm sync-openapi --ref vX` 与 `pnpm gen`。

  打 tag 之前可以在 `server/go.mod` 临时加 `replace` 指向本地 panel-spec 联调，但不要合并；`make check-spec-version` 会拦住。
- **本地运行 panel 的 `make ci`**：
  - 需要 `GOTOOLCHAIN=go1.27.1`、`PANEL_REQUIRE_DB=1`、`PLAYWRIGHT_CHROMIUM_EXECUTABLE=/opt/pw-browsers/chromium`，PATH 中包含 `~/go/bin`（buf、goimports）。
  - Docker 守护进程可能需要手动启动。
- **本地运行 panel-spec 的 `make ci`**：本机 Go 版本会重排 `gen/go/node/v1/envelope.pb.go` 中的注释，使 `check-generated` 失败。这与改动无关，不要提交该文件；GitHub CI 不受影响。
- **提交约定**：
  - 一次提交只改一个仓库（ARC-02）。
  - 用 `git commit -s` 签署 DCO。
  - 提交信息用中文，写明依据的规则编号。
