## 计费对抗验证（billing-verifier，负责人裁定）

| 编号 | 问题 | 裁定 | 落点 |
|---|---|---|---|
| V1 | 剩余价值按整段时间比例计算：低价短周期后接高价长周期续费再升级，可多得剩余价值（示例约 18 元） | 按笔计算：每笔付款只覆盖自己的区间（开通为 [`starts_at`, 首个 `expires_at`)，续费为其顺延区间）；时间部分 = Σ 各笔实付 × 该笔剩余比例（已过去为 0，未开始为 1）；流量部分 = 本段实付 × 流量剩余比例（整段、实际各周期额度之和）；剩余价值 = floor(min(时间部分, 流量部分))，精确有理数运算、最后一步取整。各笔记录在 `purchase`、`redeem`、`renew`、`upgrade`、`downgrade_immediate`、`downgrade_applied` 事件的 `diff.tranche`（`{paid_minor, covers_from, covers_to}`）。“本段实付”中带入的剩余价值只计抵扣新价格的部分，记入余额的超出部分不计 | spec/11 BIL-20、BIL-12；spec/00；契约 `EntitlementEvent.diff` |
| V2 | “只按时间”模式下不限流量与限量之间切换，预置为 0 可重置用量 | 目标不限：预置为旧已用量；由不限改为限量：min(旧已用量, 新额度)；其他沿用 ceil 公式 | spec/11 BIL-12 |
| V3 | 只有自然月首个周期折算，被本段终点截断的周期拿到整周期额度 | 被本段起点或终点截断的每个周期都折算：floor(q × 周期在本段内的秒数 ÷ 完整周期秒数)，包括立即降级的新段、自然月的最后一个周期、天数不是周期整数倍的一次性套餐；本段终点移动时重算当前周期额度 | spec/11 BIL-16、BIL-20、BIL-23；spec/03 `usage_cycles.bytes_limit` |
| V4 | 一次性套餐续费（叠加）可取 `period_days` 不同的低价行，并把锁定移过去 | 周期为（`period`、`period_days`）；只与相同 `period_days` 的在售行取 min，没有时按锁定价格；锁定不移到 `period_days` 不同的行；BIL-08 不适用；顺延锁定行的 `period_days` | spec/11 BIL-07、BIL-09 |
| V5 | 立即降级的新段时长无上限，剩余价值大时可换到远超一个周期的低档服务 | 新段至多所选价格行的一个周期；超出金额的剩余价值记入余额，新原因 `downgrade_surplus`；`paid_minor` = min(剩余价值, 金额)。数据库 CHECK 需迁移（panel），契约的筛选枚举与 `x-extensible-enum` 增加取值（非破坏） | spec/11 BIL-23；spec/12 ORD-16；契约；panel 迁移 |
| V6 | ORD-06 临界续费开通时是否重新定价 | 价格在报价与下单时确定；ORD-05 的重算仍按续费场景与报价时的锁定价格，不改按新购。领域层规则 | spec/12 ORD-06 |
| V7 | 退款（ORD-10）后各笔的金额与区间未定义 | 退款事件的 `diff.tranches` 给出调整后的完整列表：从最晚的一笔扣减金额，当前时刻之后的区间按 ORD-10 的比例缩短。实现在 M1-06 | spec/12 ORD-10；spec/11 BIL-20；backlog M1-06 |
| V8 | 管理员修改 `expires_at` 后的分笔 | 延长追加实付 0 的一笔；缩短时截断越过新终点的各笔，实付按保留秒数比例向下取整，差额不退回；`diff.tranches` 给出完整列表 | spec/11 11.6、BIL-20 |

## 工具决定（spec-owner 提出，负责人接受）

- **`x-sensitive-fields`**：管理接口 OpenAPI 新增扩展，列出“只在修改这些字段时才敏感”的字段（首例 `PATCH /v1/settings` 的 `free_plan_id`）。修改所列字段时按敏感操作校验 `reason` 与 `Mfa-Assertion`，否则按普通操作处理；`tools/checkapi` 校验带此扩展的操作声明了 `Mfa-Assertion` 与 401，且请求体 schema 含所列字段与 `reason`（R1），并有测试。
- **按 tag 的 `oasdiff-ignore.txt`**：panel-spec 的 `make breaking-openapi` 读取与规范同目录的 `oasdiff-ignore.txt`（`--err-ignore`），每行为 oasdiff 报告原文，只对下一个 tag 有效（文件中 `# target: vX.Y.Z`，不晚于上一个 tag 时检查失败，见 R12），只作用于同目录的规范，理由写在 CHANGELOG，打出该 tag 后清空。v0.10.0 只登记一项：`GET /v1/accounts/{id}/credit-entries` 的 `reason` 筛选移除 `proration_refund`（P1，与数据库 CHECK 对齐）。
